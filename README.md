# CheckATS

Free ATS resume checker + AI HR review for tech job seekers.
Live: https://checkats.online

## Repo layout

- `pages-deploy/` — the static site (what Cloudflare Pages serves). `index.html` is the
  tool; `guide/` holds the SEO articles; `sitemap.xml`, `robots.txt`, `llms.txt` included.
- `cloudflare/hr-review-worker.js` — the Cloudflare Worker behind the site:
  `/api/hr-review` (4-dimension AI review), `/api/rewrite` (DeepSeek rewrite),
  `/api/send-email` (Resend), `/api/feedback`. Secrets (`DEEPSEEK_API_KEY`,
  `RESEND_API_KEY`, `ADMIN_PASS`) live as Worker secrets, never in this repo.
- `cloudflare/ai-proxy-worker.js` — older standalone proxy (kept for reference).
- `guide-topics.md` — SEO article topic queue for the guide section.

## Deploy

Static site → Cloudflare Pages project `ats-resume-optimizer`
(custom domains `checkats.online`, `www.checkats.online`):

```bash
echo '{"project":"ats-resume-optimizer","dir":"<repo>/pages-deploy"}' \
  | python3 ~/workspace/skills/cloudflare/bin/pages_deploy.py
```

Worker → `wrangler deploy` (or the Cloudflare dashboard); set secrets with
`wrangler secret put DEEPSEEK_API_KEY / RESEND_API_KEY / ADMIN_PASS`.

## Sync workflow (Muse + local agent)

This repo is the source of truth. Two agents work on it:

1. **Muse** (cloud) pushes site/content changes here, then deploys.
2. **Local agent** (user's computer) pulls, works (e.g. UI redesign), pushes.

Rules: always `git pull` before starting work; never force-push; one concern per
commit; never commit secrets (`.gitignore` covers the usual suspects).

  JD keyword coverage 60% + plain-text parsability 40%.
- No login / paywall by decision (2026-10-11). Do not reintroduce paid UI
  without the owner's go-ahead.
- The UI uses the owner-approved Craft-inspired editorial design: warm cream

## Local preview

Serve `pages-deploy/` with any static HTTP server, for example:


## PDF preview and native-text export

PDF upload now retains the source document and extracts positioned text blocks.
The local PDF workbench shows the original pages, extracted reading order,
empty/garbled text warnings and a possible multi-column warning. These are file
extraction diagnostics, separate from the existing four-check simulated score.

For supported text PDFs, AI Rewrite sends an additional `pdfBlocks` array of
paragraph IDs, text and fixed-length hints. The Worker returns the same IDs and
protects headings/contact lines. **Deploy both `pages-deploy/` and the updated
`cloudflare/hr-review-worker.js` together.** An older Worker can return text, but
cannot supply the paragraph map required for a PDF preview/export.

The exporter copies the original page geometry and graphics, removes the old
text-painting operators (including Form XObjects), and draws selectable native
PDF text. It does not use screenshots or paint white rectangles over old text.
The exact generated bytes must pass a PDF.js text round-trip before download.
Added/replaced words are highlighted in an HTML overlay only; exported bytes
never include that overlay. Paragraph edits invalidate the previous download
until the preview is rebuilt and validated.

### Supported scope and layout limits

- Text PDFs up to 10 MB / 10 pages / 240 blocks. Mapped AI rewriting has an
  8,000-character limit, rejected explicitly instead of truncating the source.
- Original page size, text positions, font size/family/style categories, color,
  rules and graphics are reused. Arbitrary embedded fonts are substituted with
  standard PDF fonts or a bundled static Noto Sans SC font; pixel-identical font
  reproduction is not promised. CJK exports embed the full static font because
  fontkit subsetting can lose visible outlines while still passing text parsing.
- Rewritten prose must fit the original region, with at most a 10% font-size
  reduction. Overflow blocks export and identifies the paragraph for shortening.
  Content is not silently clipped, pushed over rules, or flowed to extra pages.
- Scans/empty pages, garbled text, rotated pages/text, widgets/signatures, inline
  binary images, text clipping/invisible layers, and unsupported content streams
  remain preview-only. There is no OCR. Multi-column reading order needs manual
  review. This is an editor, not a secure redaction tool or an employer ATS.
- Standard text must remain selectable/extractable; editing the resulting PDF
  further depends on the PDF editor's native-text support and installed fonts.
- No PDF bytes or graphics leave the browser. Optional AI receives extracted
  text only. TXT download/copy/email remain available as before.

### Development and verification

```bash
npm ci --ignore-scripts
npm run vendor
npm test
npm run test:scoring
python -X utf8 scripts/verify-seo.py
python scripts/verify-pdf-render.py
```

The render check uses PyMuPDF (`python -m pip install pymupdf`), verifies every
non-space glyph has visible ink, and writes synthetic QA renders to `tmp/pdfs/`.
Unit tests cover native output, old-text removal, multipage/Chinese text, Form
XObjects, overflow, unsupported documents and Worker mapping validation.

`node scripts/preview-pdf.cjs` serves a localhost-only QA page on port 4178 with
fictional resume fixtures and mocked AI. Its fixture buttons are injected by the
test server and are not in production assets. No real AI calls or user documents
are used. A production-like static preview can still be served as described above.

PDF dependencies and licenses are self-hosted under `pages-deploy/vendor/`.
The CJK font is loaded only when needed. To refresh its upstream source and
instantiate the static regular font, run `node scripts/fetch-pdf-font.cjs` with
Python `fonttools` installed. Review font appearance after any font/library update.

## SEO and GEO checks

Public pages use the CheckATS name, self-canonical URLs, crawlable guide links, and factual structured data. `/methodology/` documents the actual local score and external data processing. `llms.txt` is an optional summary, not a search inclusion requirement.

Run `python3 scripts/verify-seo.py` and `node scripts/verify-scoring.cjs` before publishing. After deployment, submit the sitemap and inspect public URLs in Search Console and Bing Webmaster Tools. Confirm CDN crawler access and track tool usage from organic and AI referrals.
